## ผ่าน (ยืนยันซ้ำได้ตรงกับรายงานเดิม)

- `device_type` 1,961 / 71 / 71 และ `external_condition` 432 / 51 / 51 ตรงกับ README
- ทุก `group_id` ในไฟล์ split ตรงกับ `groups.json` ไม่มี group ซ้ำข้ามชุด และไม่มีภาพหาย
- `new_split` ใน `cleaned_images.jsonl` ตรงกับไฟล์ split ทุกภาพ

## ข้อสังเกต

- `image_id` **ไม่ใช่** SHA-256 ของไบต์ไฟล์ปัจจุบัน (ไม่ตรงทั้ง 2,103 ภาพ) อาจเป็น hash ของต้นฉบับหรือ record อย่าใช้ตรวจความถูกต้องของไฟล์

## ปัญหาที่พบ (ต้องแก้ก่อนเชื่อคะแนนโมเดล)

### 1. มือถือ: ความละเอียดภาพบอกป้ายได้เกือบทั้งหมด (สำคัญที่สุด)

- mobile / visible_damage = 150×150 ทุกภาพ (train 50, val 11, test 11) เป็นสมาร์ตโฟนที่ถ่ายจริงจากแหล่งเดียว
- mobile / no_visible_damage ส่วนใหญ่เป็นภาพไม่จัตุรัส ความละเอียดสูงกว่า และเป็นโทรศัพท์ปุ่มกดหรือรุ่นยุค 2000s
- แค่กฎ "ภาพ 150×150 → เสียหาย" ก็ทาย mobile test ถูก **22/23 (96%)** ทั้งที่ไม่ได้ดูภาพเลย
- ผลคือคะแนน mobile ใน test ปัจจุบันวัดว่าโมเดลแยกแหล่งที่มาได้หรือไม่ ไม่ได้วัดความสามารถตรวจรอยแตก

### 2. ภาพซ้ำข้ามชุดที่ hash เดิมจับไม่ได้

- validation `visible_damage/scope/laptop/23d473192e43…` กับ train `visible_damage/scope/laptop/d2fbd9bc8b63…` เป็นภาพ stock เดียวกันที่ต่างลายน้ำ (Shutterstock / Depositphotos) ดู `pairs.jpg` แถว 2
- อีก 3 คู่ที่ dHash ใกล้กันเป็นคนละอุปกรณ์ (false positive)
- ในมือถือเสียหายพบฉากหลังซ้ำข้ามชุด เช่น ผ้าลายแดง และเก้าอี้สำนักงาน (ดู `mobile_damage_all.jpg` ป้ายแดง = val/test) อาจเป็นผู้ถ่ายหรือเครื่องเดียวกัน ต้องให้คนตรวจ

### 3. ขนาดชุดประเมินเล็กมาก

- laptop no_visible_damage ใน test มี 8 ภาพ ผิด 1 ภาพเท่ากับเปลี่ยน 12.5 จุด
- printer ใน test มี 3 ภาพ คะแนนรายคลาสจึงไม่มีความหมายทางสถิติ

### 4. Train ส่วนใหญ่ยังไม่ได้ตรวจชนิดภาพ

- external_condition train: no_visible_damage ยังไม่ตรวจ 262/287 ภาพ ส่วน visible_damage ยังไม่ตรวจ 85/145 ภาพ
